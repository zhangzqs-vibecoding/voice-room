# 多人视频会议设计

## 目标

在现有 Voice Room 的 LiveKit SFU 架构上增加腾讯会议式多人视频会议能力，同时保留身份选择、低延迟语音、设备选择和发言状态显示。

## 已确认范围

- 创建者可在创建会议时选择人数上限，服务端硬上限为 50 人。
- 任何拿到参会链接的人都可以输入昵称/身份入会，不设置会议密码和审批流程。
- 创建会议后生成独立的主持人链接和普通参会链接。
- 主持人可静音他人、关闭他人摄像头、移出成员、锁定会议和结束会议。
- 默认视频质量为 720p，WebRTC 根据网络和人数自适应降级。
- 界面采用“当前发言人主画面 + 其他成员网格”布局；50 人时成员网格分页或滚动显示。
- 支持摄像头、麦克风、屏幕共享、文字聊天、举手和当前发言人高亮。
- 支持浏览器本地合成录制：Canvas 合成画面，Web Audio 混合声音，停止后下载 WebM 文件；不上传录像到服务器。

## 架构

浏览器继续使用 `livekit-client` 连接 LiveKit。API 负责创建房间、签发短期 Token 和校验主持人凭证；LiveKit SFU 负责音视频转发，Redis 负责 LiveKit 状态。

```text
浏览器 -- HTTPS API --> API -- RoomService --> LiveKit
   \---------------- WebRTC ----------------> LiveKit SFU
```

主持人链接携带独立的主持人凭证。API 只为该凭证签发带主持权限的 Token；普通参会链接只能获得普通发布/订阅权限。主持人刷新页面后可继续使用主持人链接，直到房间结束或链接过期。

## 前端模块

### meeting-session

封装 LiveKit 房间连接、麦克风/摄像头/屏幕轨道发布、远端轨道订阅、成员加入离开、发言状态和重连状态。

### meeting-layout

渲染当前发言人主画面和其他成员缩略网格。摄像头关闭时显示身份头像；超过可视数量时使用分页或滚动成员栏，避免同时渲染 50 个大视频元素。

### meeting-controls

提供静音、摄像头、屏幕共享、聊天、举手、录制、设备选择和主持人控制，并展示浏览器权限拒绝、设备断开和网络重连提示。

### local-recorder

使用 Canvas 按当前布局合成视频画面，使用 Web Audio 将本地和远端音轨混合，再通过 `MediaRecorder` 生成文件。优先使用 VP9/Opus，浏览器不支持时回退到可用的 WebM 编码。停止录制后立即触发下载，录制数据不上传。

## API 变化

- 创建房间请求新增 `maxParticipants`，只接受 2–50 的整数。
- 创建房间响应同时返回 `hostUrl` 和 `participantUrl`。
- 加入接口根据链接凭证签发普通或主持人 Token。
- 主持人控制接口拒绝普通 Token，并返回明确的权限错误。
- 房间已满、房间过期、凭证无效和 LiveKit 不可用均返回稳定的错误码。

## 错误处理

- 摄像头/麦克风权限被拒绝：允许仅观看或稍后重试。
- 屏幕共享结束：自动移除共享轨道，恢复摄像头布局。
- 设备断开：标记对应轨道不可用，并提供重新选择设备入口。
- 网络中断：显示重连状态；超过重试窗口后提供重新入会操作。
- 录制编码不可用：提示浏览器不支持并保留会议通话，不影响其他功能。

## 验证计划

- API：人数范围、主持人/普通 Token 权限、房间满员和错误码测试。
- Web：轨道发布/订阅、发言人布局、成员状态、控制栏和设备选择测试。
- 录制：合成画面、混合音频、停止下载、编码回退测试。
- 交互：屏幕共享结束、权限拒绝、设备断开、网络重连和主持人操作测试。
- 构建：完整测试、类型检查、lint、生产构建和 Compose 配置校验。

## 非目标

- 不实现服务器端录制或对象存储。
- 不实现账号系统、会议密码、入会审批、日程预约和会议计费。
- 不把现有 LiveKit SFU 改造成浏览器 P2P 架构。
